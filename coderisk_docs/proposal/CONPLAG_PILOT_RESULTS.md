# ConPlag Java 公开标签探索结果

工作日期：2026年10月9日。结论限定于本次公开单人标签、题目分组和固定阈值方案；尚不是正式毕设验证。

## 1. 结果与范围

当前融合配置在两个视图的测试集上均未取得最高 F1。移除规范化和映射后的方法 F1 高于完整融合，说明当前配置在这批数据上没有体现预期的增益，需要后续在独立开发数据中检查原因。不能据此把“规范化必然提高效果”写入论文；也不能将单数据集结果推广成所有规范化方法无效。

运行前方案、程序指纹和样本划分已通过提交 `34dfd1707eb75d055f60a6b41ed6ddb15563621b` 上传 GitHub，随后才运行本次代码对评分。客户端日期与实际系统 UTC 时间分开保存，冻结时刻以 JSON 中的实际时间为准。[运行前记录](../../coderisk/experiment/evidence/conplag-registration-20261009/README.md)。这是项目内部的运行前留档，不是外部注册研究。

使用 ConPlag v3 的 911 对 Java：公开正标签 251、负标签 660。按 21 个题目分组，验证 284 对、测试 627 对；测试包含正标签 164、负标签 463，15 个题目。题目、已知提交家族、原始与去模板文本哈希跨集合重叠为零；作者身份不可用，不声称作者隔离。

原始和发布者去模板源码为同一批样本的两个视图，各自选择验证阈值，不能合计为 1,822 个独立样本。“去模板”是发布者提供的处理结果，未由本项目验证为完整模板去除或语义保持，也不能从两个视图推断单独处理因素的因果效果。[发布者记录](https://zenodo.org/records/7332790)。

## 2. 同一集合的比较

阈值候选为 0.05 至 1.00、步长 0.05；仅按验证集最大 F1，平局取较低 FPR、再取较高阈值。完整融合保持当前生产权重；消融移除规范化与映射，将保留的 raw/AST 权重归一为各 0.5，不用测试集调融合系数。结构或规范化不可用时采用已登记的 raw 回退。JPlag 6.2.0、最小匹配 Token=5，各题目分别分析。

PICAS 全测试集合结果也独立保留：原始融合 F1=0.5543（TP=74、FP=29、TN=434、FN=90）；去模板融合 F1=0.6974（TP=106、FP=34、TN=429、FN=58），都按 627 对计算。不能将全集合某方法的数值与共同集合另一方法直接拼接比较。

## 4. 由结果推动的后续工作

1. 以已保存的公开标签不一致案例建立开发诊断清单，核查简化 Java 结构、作用域规范化和映射覆盖，分别记录“程序问题”“标签不确定”“表征局限”；不能把算法漏报当作标签错误。
2. 在独立开发集检查规范化是否稀释有效原始差异、长代码/共同输入模板是否影响序列相似度，修复后保留前后版本；本批测试已经用于观察，后续调参结果不得继续称为未见测试成绩。
3. 获取新的题目描述、可核实的独立解答和自然相似负例，完成双人复核后重新冻结，以相同综合分数比较固定与动态阈值，才能验证 RQ1。
4. 开题可据实说明：系统已实现，公开数据探索评测已经运行，正式验证尚待数据建设；论文结果章节先使用本记录作为前期探索，不预写最终效果结论。
