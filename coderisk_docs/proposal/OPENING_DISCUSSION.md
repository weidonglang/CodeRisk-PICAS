## 1. 一句话介绍

我准备做一个面向编程作业的代码相似风险检测系统，在代码相似度基础上加入题目条件和作用域标识符规范化，输出可追溯的证据，并通过实验验证它在什么情况下有效。

## 2. 约3分钟介绍稿

老师您好，我拟定的题目是“基于题目感知与标识符规范化的编程作业代码相似风险检测系统设计与实现”。研究对象限定为同一道编程题的 Java 或 Python 同语言代码提交。

选题主要考虑两个问题。第一，同题作业可能共享输入输出模板和解题套路，高相似未必代表存在复制关系，需要结合题目解释。第二，改变量名、参数名或函数名会改变代码表面表示，需要考察规范化能否保留改写关系，同时控制对独立解答的误报。

当前已经有系统原型，采用 Vue 前端、Spring Boot 业务服务和 Python 分析服务，支持题目、代码上传、检测任务、结果查询和 HTML 报告。分析部分包括 Token n-gram、基础结构、作用域标识符规范化与映射信号。题目画像由规则生成，再计算有上下界的动态阈值。输出包括综合相似度、阈值、风险边际及代码片段，供人工复核。

开题后的重点是完善研究证据。我准备先明确数据来源和标签标准，把有已知派生关系的改写作为正例，把具有独立来源依据的解答作为负例，再按题目和来源家族隔离验证集与测试集。固定阈值与动态阈值使用相同综合分，参数只在验证集选择；规范化实验明确移除哪些指标，并与 JPlag 在共同有效样本上比较。

目前实验工具已经可以生成阈值选择记录、混淆矩阵、分组统计和图表，也已在合成种子数据上实际运行。这样的结果能说明流程可用，真实作业上的效果仍待验证。Java 结构解析属于简化实现，跨语言语义分析不作为本次必须完成的主线。

我希望先请老师确认选题范围，以及是否能够获得经授权的作业或独立解答。接下来会围绕数据、公平实验、失败案例和核心缺陷修复展开，使最终论文能够同时说明系统实现和方法适用边界。

## 3. 你要能解释的完整流程

```text
同题提交 A/B → 词法处理 → 原始 Token 相似度
                    ├→ 基础结构相似度
                    └→ 作用域规范化 → 规范化相似度、标识符映射
四项信号 → 综合分 S
题目文本 → 规则画像 → 动态阈值 T
S − T → 风险等级 → 源码证据 → 人工复核
```

- Token 可以理解为程序中的词法单元，例如关键字、变量名、运算符。当前算法把连续小片段组成集合，使用 Jaccard，即交集大小除以并集大小。
- 规范化将同一作用域的变量稳定映射为统一名字，例如参数映射为 `PARAM_1`。同名但属于不同作用域的变量应分别处理。
- 当前基础结构使用节点类型序列的小片段集合。Python 来源于原生 AST，Java 来源于简化结构提取。
- 综合分正常路径为 `0.20×原始Token + 0.20×结构 + 0.45×规范化Token + 0.15×映射`。降级路径采用原始 Token。
- 题目阈值是启发式规则，还需要实验验证。自然相似风险较高时提高阈值，可能减少误报，也可能漏掉改写。
- 举例说明时可以假设 `S=0.78`：若 `T=0.82`，边际为−0.04；若 `T=0.72`，边际为0.06。两者综合分相同，风险解释不同。这是解释公式的假设值，不是实验结果。

## 4. 导师可能追问的12个问题

| 问题 | 回答思路 |
| --- | --- |
| 与普通查重工具有什么区别？ | 重点是题目条件对阈值的影响、作用域规范化和证据一致性。已有工具也有规范化和交互展示，应通过实验说明自己的适用场景。 |
| 创新点是什么？ | 目前定位为场景化方法设计与系统实现。题目阈值是否产生收益仍待检索与实验，不称首创。 |
| 为什么不直接用 JPlag？ | JPlag 是必须认真比较的基线。本课题通过自己实现和控制实验研究题目条件与风险解释，若 JPlag 更好也应如实报告。 |
| 题目难度怎么得到？ | 当前由题面长度、输入输出、约束和关键词等规则估计；不等于专家认定的真实难度，也没有训练难度预测模型。 |
| 阈值系数为什么这样设？ | 属于现有工程配置。生产规则作为一个独立方法报告；实验只在验证集选偏移量，并比较固定阈值。不能根据测试集改公式。 |
| 系统能认定抄袭吗？ | 只能提示代码相似风险。数据标签表示已知来源关系，学术违规仍需具体证据和教学规则。 |
| 为什么按题目分集？ | 同题模板、同源改写可能高度相关。如果被拆到两边，会夸大泛化效果。共享来源的不同题目也要合并分组。 |
| 正负例怎么确定？ | 正例依据明确的派生记录；负例依据独立来源记录。得分高低不能参与标签判断，关系不清楚则标为不确定。 |
| 数据不够怎么办？ | 优先取得授权数据，先做小规模标注试验；若只能获得受控独立解答，就限定研究范围和结论，不冒称真实课堂验证。 |
| 消融实验具体去掉什么？ | 去掉规范化 Token 与映射两项，剩余原始 Token/结构权重归一为0.50/0.50，分别在验证集选阈值。 |
| 如果改进效果不好？ | 保留负结果，分析误报和漏报的来源，论文仍可展示完整设计、可复现实验和适用边界。 |
| 你个人的工作是什么？ | 按实际开发、分析、验证和写作记录说明。AI 辅助部分按学校规定披露，并确保自己能解释代码和实验。 |

## 5. 第一次交流带什么

带上选题说明、开题初稿、数据规范和公平评测说明。演示按“建题→上传两个文件→检测→查看阈值与证据→导出报告”展开。另备一组改名样例、一组独立但自然相似样例和一组解析失败样例，说明系统在正常与边界情况下的行为。

导师反馈优先记录：题名与主线、预期数据来源、实验深度、学校格式与时间安排。反馈后再调整工作计划；目前不需要为了等待模板暂停数据和算法准备。
