# 语言版本与简单题自然相似：本轮实现

日期：2026-10-09。本轮新增复核背景信息，不改变生产相似度、融合权重、动态/固定阈值或公开标签资格；尚未证明减少误报或提升召回。

## 1. 语言版本记录与分析限制

代码上传可填写 `languageVersion`，例如 Python 2.7、Python 3.12、Java 17、C11。字段保存在提交表，通过后端传入分析器；历史提交默认空字符串，输出显示 UNKNOWN。内容是提交者声明，解析成功不证明版本、编译或语义正确。

结果新增 `REVIEW_NOTE` 证据，`metadata.category=LANGUAGE_COMPATIBILITY`，分别记录原始版本声明、Python 运行时、语法是否解析、规范化模式、语法线索、限制与 `sourceConverted=false`。

- Python：标记可能的旧式 print、raw_input 名称、赋值表达式；声明 Python 2 时明确说明当前 Python 3 解析器不能验证它的版本语义。遇到 `/` 进一步提示除法语义需要复核。声明高于本机 Python 次版本时提示版本范围限制。
- Java：记录简化结构解析的限制，可登记文本块、箭头语法信号；不从箭头直接推断具体 Java 版本，不声称执行完整 Java 编译检查。
- C：记录当前 Tree-sitter 和规范化覆盖，明显的 std/using namespace 信号标记为语言核验需求，不自动把 C++ 改成 C。
- HTML：记录源码结构范围，嵌入脚本和样式仍按原文处理，不验证浏览器标准版本或执行页面。

已声明的同语言版本不同，会加入复核原因。未知版本不能自动认为相同或不同。Python/Java/JDK 等前缀和空格会作保守比较，但没有建立完整版本别名数据库。

Python 2/3 既有写法差异也有行为差异；因此本轮不做未经验证的源码转换。[Python 官方版本变更说明](https://docs.python.org/3/whatsnew/3.0.html)。安全的跨版本结构对齐仍需要单独定义支持子集、保留转换映射并验证行为，尚未实现。

## 2. 共同模板登记与精确范围

新增题目时可选填 `starterLanguage`、`starterCode`、`starterSource`。填写源码时语言必须受支持、来源必须非空；来源只是登记，仍须人工确认它是公开框架、发布时间和内容范围。每个题目目前登记一个语言的模板，多语言模板应分别建立题目上下文。

模板来源记录不能证明所有匹配都是教师提供，也不能把完整参考答案当作共同框架。不会根据待测提交反推“共同模板”，不使用测试标签调整模板规则。

学生实现空位需在模板中使用独立注释行：

| 语言 | 空位标记 |
| --- | --- |
| Python | `# CODERISK_STUDENT_CODE` |
| Java/C | `/* CODERISK_STUDENT_CODE */` |
| HTML | `<!-- CODERISK_STUDENT_CODE -->` |

仅匹配模板中至少 8 个 Token 的完整连续片段。注释和格式差异按现有 Token 提取处理；改名或内容修改的模板不作模糊排除。标记出现在字符串、Java 文本块或 HTML 嵌入脚本中时不会当作空位。重复匹配按 Token 下标合并，不重复累计覆盖；展示最多 20 个范围，实际计数不受展示上限影响。

`metadata.category=SHARED_TEMPLATE_CONTEXT` 保存来源、模板 SHA-256、匹配策略、原始 Token 数、覆盖数、剩余 Token 数和原文行号。行号不因模板排除发生移动。诊断性的 `nonTemplateTokenSetSimilarity` 比较剩余原始 Token 值集合，避免排除片段后拼接出虚构的连续 n-gram；它不含顺序、频率或语义，不等于生产 Token 分数。任一侧无剩余 Token 时为 null，不补零。

模板覆盖与剩余代码量只用于背景解释，没有自动替换综合分，也不能将匹配模板之外的代码认定为独立或派生。

## 3. “可区分依据不足”与相似分数并列

新增 `metadata.category=REVIEW_ASSESSMENT`，策略版本 `context-review-v1`：

| 状态 | 含义 |
| --- | --- |
| INSUFFICIENT_DISTINGUISHING_EVIDENCE | 至少一侧非模板代码太少，或题目自然相似启发式高而剩余实现空间有限，需要更多来源证据 |
| CONTEXT_REVIEW_REQUIRED | 存在版本、解析、跨语言、模板或自然相似背景，需要结合背景复核 |
| SIMILARITY_SIGNALS_ONLY | 当前仅有相似信号，仍未确认关系；不是独立创作认证 |

当前试行规则：任一侧剩余 Token 不超过 40；或非 HTML 题目自然相似启发式不低于 0.60 且任一侧剩余 Token 不超过 120，提示依据不足。模板覆盖至少一侧达到 50% 时另加模板主导原因。**40/120/0.60/50% 都是未校准的开发规则**，不代表概率、统计显著性或学术界通用门槛。长代码也不会被自动认定为证据充分。

HTML 不套用算法题画像；空代码和纯注释没有有效依据。存在版本/解析问题时，低分同样不证明独立创作。规则不把简单计算器的高相似变成“抄袭”，也不自动把低相似变成“没有关系”。

前端详情页把提示、声明版本、有效 Token 数、模板覆盖和诊断分放在原始风险结果旁边；后端 HTML 报告保存相同复核说明和结构化元数据。原有 riskLevel、exceedThreshold 和任务风险计数仍由相似分数/阈值计算，不是经过人工确认的关系标签。

## 4. 验证数据与正式研究边界

新增 15 项 Python 回归及 2 项后端集成测试，覆盖短计算器、旧式写法、版本声明、除法语义、模板范围、字符串中的标记、重复匹配、空剩余代码、HTML 领域隔离、参数校验、持久化、分析请求与报告转义。

另运行八个合成开发案例，覆盖 Java/Python/C/HTML；实际输出见 [证据](../../coderisk/experiment/evidence/review-context-20261009/README.md)。它们是本项目编写的诊断样例，关系标签全部 UNCERTAIN、正式指标资格为零，不能把不同写法当作可信独立负例。每例均核对新增上下文前后的生产分数与阈值相同。

全量验证为 Python 126 项、后端 12 项通过，前端类型检查与构建成功。另用真实后端及 Python 服务、隔离临时 H2 内存数据库完成合成 Java 计算器联调：版本 8/17、多行模板、7 个剩余 Token、相似分 1.0 与“依据不足”提示均保存并导出。结果页经过浏览器截图及视觉核验。这不是完整上传页浏览器测试，也没有完成 MySQL 实库迁移验证。

此前 ConPlag 的运行前方案冻结了源码指纹。本轮改变了分析器实现文件，重现历史结果应检出旧提交 `34dfd1707eb75d055f60a6b41ed6ddb15563621b`；新实现不会绕过旧方案的指纹门禁。历史结果没有据此重新包装为新版成绩。

## 5. 后续校准与版本对齐

下一轮正式数据须登记题目、语言/版本、共同模板、作者或来源家族、功能证据及独立/派生依据。计算器至少区分“两个数四则运算”和“表达式解析、括号、优先级与错误恢复”，不能仅凭标题划难度。

使用预先登记、核验的独立参考解建立自然相似背景；规则和使用范围先冻结。阈值或诊断门槛仅在验证集选取，测试提交及标签不参与调参。分别报告简单题自然相似误报、真实派生漏报、版本兼容覆盖与无法判断比例。当前公开数据仍缺足够自然相似标签和作者依据，本轮不宣称完成这些实证结论。
