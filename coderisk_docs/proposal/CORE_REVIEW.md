# 核心代码检查与修复记录

日期：2026年10月8日。属于定向正确性检查，不代表完整 Java 编译器实现或所有边界已覆盖。

## 已复现并修复的问题

| 问题 | 修复前表现 | 当前处理与验证 |
| --- | --- | --- |
| Java 行/块注释改变坐标 | CRLF、多行注释后Token行号和列号偏移，例子中原第3行变成第5行 | 原位空格遮罩，保留每个CR/LF和字符长度；逐Token检查原码位置 |
| 字符串/字符中的括号参与配对 | 合法字符串 `"("` 或字符 `'}'` 被判定解析失败 | 对词法单元配对，只识别独立括号Token |
| 文本块与未闭合注释 | 文本块可能被拆分，未闭合注释被部分吞掉 | 文本块保留为单Token；未闭合注释/字面量产生解析告警 |
| 调用被误识别为方法声明 | `if (ok(n)) {…}` 中 `ok` 在局部被声明为新函数 | 限制声明后缀和前缀，正常调用解析至原方法作用域 |
| `this`字段被局部参数遮蔽 | `this.value` 绑定到同名参数；`other.value` 也错误套用局部名 | `this`只查询最近类作用域的成员；未知外部对象成员保留原名 |
| 映射显示上限影响评分 | 超过20个改名符号后提前退出，未统计的符号降低一致性 | 全量计算统计，只截断展示；0/3/20/100不同限额分数一致 |
| Python 中文标识符列偏移 | AST字节列与Token字符列不一致，参数及引用漏绑定 | 映射UTF-8字节偏移到字符列，核对全部出现位置 |
| AST证据范围倒置/回到第1行 | 无源码行号的Load/Store/Add默认落第1行，前序序列不保证行号递增 | 无位置节点继承父节点行号，窗口取最小/最大行；仅表示近似覆盖区域 |
| 多行字符串的证据结束行 | 只记录Token起始行，片段截不到字符串结束 | Token增加结束行，Java文本块和Python三引号字符串均验证 |
| 降级指标权重不一致 | AST可用但规范化失败时，显示权重可能不等于实际Token降级 | 权重与实际规范化可用状态一致，正常融合系数保持不变 |

新增回归在 `analysis-service-python/tests/test_parser_boundaries.py`；第一次运行11个用例出现9个失败，修复后全部通过；随后补充了多行字符串用例。评分展示上限等问题会影响历史分数，因此新结果使用新的运行目录和源码哈希，不能覆盖旧实验。

## 公平评测与数据代码验证

`test_fair_evaluation.py` 验证：测试标签/分数变化不会改变阈值选择；消融移除两项规范化信号并保留降级；零分母不伪装成完美结果；来源家族传递分组与确定性划分；跨集合来源家族被拒绝；配对分组抽样可重复；JPlag失败不会丢失请求代码对。

JPlag适配器新增UTF-8、最低输出阈值和完整日志，失败时保留每个代码对的缺失状态，数值越界或冲突的重复记录报错。执行路径统一绝对化，避免工作目录改变后找错输入。

## 仍需明确保留的限制

- Java仍是词法与基础结构解析，不是完整语法、类型或重载解析。Unicode转义预处理、完整泛型声明、lambda、record、模式变量、循环变量的精确生命周期、复杂继承及外部成员解析尚未全面覆盖。
- 同一个类中的字段与方法同名、重载方法等命名空间复杂情况需要进一步测试；当前修复不能推广成“所有作用域均正确”。
- Python的global/nonlocal、推导式独立作用域、导入别名、类与方法名字查找、复杂注解等仍有覆盖缺口。当前Unicode修复不解决这些语义问题。
- AST节点类型n-gram证据是结构线索，覆盖行区间不等于精确子树克隆；相同结构也可能来自独立解答。
- 外部对象成员保留原名会降低部分改名场景的召回，这是缺少类型解析时保守处理的代价。
- 暂不宣称任意改名、结构重排或跨语言语义等价均被正确处理。

下一轮应优先围绕真实样本暴露的边界扩充测试，再评估是否引入成熟Java解析器；不得按测试集得分反复修改后仍称独立测试。

## 核查依据

Python位置修正依据 [Python AST官方文档](https://docs.python.org/3/library/ast.html#ast.AST) 的UTF-8字节偏移定义；作用域语义参照 [Java 21语言规范第6章](https://docs.oracle.com/javase/specs/jls/se21/html/jls-6.html)。这些规范为核查依据，不表示简化解析器已经实现全部语言规则。
