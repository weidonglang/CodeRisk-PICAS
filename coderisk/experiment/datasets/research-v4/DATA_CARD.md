# CodeRisk Research V4 Dataset Card

## Status

`coderisk-research-v4-seed-1.0` is a synthetic seed dataset for validating the Research V4 data and experiment workflow. It contains 91 pairs: 80 same-language and 11 Java/Python pairs. All 91 rows declare `data_origin=SYNTHETIC`; 87 use `source_type=synthetic` and 4 AI rewrite placeholders use `source_type=placeholder`. The placeholders are excluded from core metrics. This dataset is not a real benchmark.

## Directory contract

```text
research-v4/
  dataset.json                 aggregate shard manifest
  case.schema.json             manual-pair metadata schema
  DATA_COLLECTION_GUIDE.md     data collection and leakage-prevention workflow
  manual_case.template.json    excluded example
  seed_pairs.json              generated synthetic seed shard
  pairs/manual_pairs.json      loaded manual metadata shard
  samples/seed/...             synthetic seed source files
  samples/manual/...           manually supplied source files
  samples/ai_assisted/...      verified AI-assisted rewrites only
  samples/external/...         public or authorized external samples
  samples/synthetic/...        extra synthetic workflow probes
  samples/placeholders/...     incomplete rows excluded from core metrics
  templates/...                metadata and README templates
```

The template is never included in statistics or experiments. `seed_pairs.json` is deterministic scaffold data generated by `build_research_v4_seed.py`; traceable additions belong in `pairs/manual_pairs.json`.

## Required metadata

Each pair records `pair_id`, `problem_id`, `problem_type`, `problem_group`, `dataset_split`, `split_preregistered`, `source_id`, `experiment_label`, `case_type`, `language`, `language_a`, `language_b`, `dataset_version`, `data_origin`, `source_type`, `synthetic`, `eligible_for_core_metrics`, question metadata, two relative code paths, provenance, optional notes, and computed SHA-256 hashes.

Allowed labels and case types follow `coderisk_docs/ENUMS.md`. `UNCERTAIN` cases remain available for parser/failure analysis but cannot enter core classification metrics.

## Isolation rules

1. A `problem_id` may appear in only one split.
2. A transformation/source family `source_id` may appear in only one split.
3. Exact source-code content hashes may not cross validation/test.
4. Manual code paths must stay under this dataset directory.
5. Test labels and thresholds must not be changed after inspecting test results.

The 36-case V3 shard retains its pre-existing problem split. The 7-case legacy cross-language shard had no split metadata in Phase 2; its Phase 3 split is marked `split_preregistered=false` and remains exploratory. The new seed problems and every future manual case assign their split before result inspection.

## Provenance and AI-assisted cases

Non-synthetic cases require a license or authorization statement. An `AI_REWRITE` case is eligible for core metrics only after recording model name, prompt template, generation time, `manual_check_status=VERIFIED`, and `functional_check_status=PASSED`. These cases evaluate retained structural similarity after assisted rewriting; they do not evaluate whether code was AI-generated.

## Validation and experiment commands

If the Windows `python` alias is blocked, set `$PY` to the analysis-service virtualenv:

```powershell
$PY = ".\analysis-service-python\.venv\Scripts\python.exe"
```

```powershell
python experiment\validate_research_v4_dataset.py
python experiment\run_research_v4.py --config configs\experiments\research_v4.json --run-id <immutable-run-id>
```

The validator reports coverage gaps without inventing real samples. The runner emits dataset statistics, same-language E1-E5, validation-only calibration, the experimental cross-language matrix, external-baseline status, failure/borderline files, and paper-table CSV files.

## Adding a case

1. Put both code files below `samples/manual/<problem-id>/`.
2. Run `python experiment/add_research_v4_case.py --help` and provide the required identifiers, split, labels, languages, paths, and provenance.
3. Review `pending_confirmation_fields`; add authorization/source details and, for AI-assisted rewrites, model, prompt, generation time, manual verification, and functional verification.
4. Use `--append` only after no confirmation field remains, then run the validator.

The helper computes hashes and refuses unsafe paths or duplicate `pair_id` values.

Detailed add-data workflow, source-type definitions, priority TODOs, JPlag-friendly sample guidance, and 20/40/60-pair collection plans are in `DATA_COLLECTION_GUIDE.md`.

## Current limitations

The seed covers all requested problem and case categories for workflow testing, but this is synthetic coverage only. The declared real-data gaps are 20 `manual`, 8 verified `ai_assisted`, and 8 `external` pairs. JPlag 6.2.0 aligns 72 eligible same-language seed pairs; 19 exclusions are recorded. Dolos has not been run. No result may be used to claim confirmed plagiarism, complete semantic equivalence, AI-code detection, or final benchmark quality.
